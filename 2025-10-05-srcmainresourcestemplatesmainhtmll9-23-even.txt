> when i give action , i have to give this @src/main/resources/templates/main.html#L19-22 but when i use th:action i don't have to use this why 
  ⎿  Read src/main/resources/templates/main.html (4 lines)

● ★ Insight ─────────────────────────────────────
  When you use th:action="@{...}", Thymeleaf automatically injects
  the CSRF token as a hidden field. With plain action="...", you
  must manually add it. This is Spring Security's integration with
  Thymeleaf working behind the scenes to reduce boilerplate.
  ─────────────────────────────────────────────────

  The difference:

  <!-- Manual: You add CSRF token yourself -->
  <form action="/product/add" method="post">
      <input th:name="${_csrf.parameterName}" 
             th:value="${_csrf.token}" 
             type="hidden"/>
  </form>

  <!-- Automatic: Thymeleaf adds it for you -->
  <form th:action="@{/product/add}" method="post">
      <!-- CSRF token automatically injected here -->
  </form>

  When Thymeleaf sees th:action on a POST form, it automatically inserts:
  <input type="hidden" name="_csrf" value="actual-token-value"/>

  So th:action = less code, automatic CSRF protection. The @{...} syntax also handles:
  - Context path prefixing (if your app runs at /myapp/product/add)
  - URL encoding
  - Path variables

  Using th:action is the recommended approach for Spring applications with Thymeleaf.

> how can client send xor enabled version, can't my backedn handle that 

● Yes! Your backend automatically handles XOR encoding/decoding. Here's how it works:

  Flow:
  1. Backend generates: Raw UUID 66adfb44... → saves to DB
  2. Backend sends to client: XOR-encoded NjZhZGZiNDQtY2JlMy00ODJmLWFiYjktYTQxNzZmOTlhZGFhqT8yS... (twice the length)
  3. Client receives: XOR-encoded token in HTML/JSON
  4. Client sends back: Same XOR-encoded token (no change needed)
  5. Backend receives: Automatically decodes XOR → compares with DB

  ★ Insight ─────────────────────────────────────
  XOR encoding is transparent to clients. Spring's XorCsrfTokenRequest
  AttributeHandler encodes on the way out and decodes on the way in.
  Clients just echo back what they receive - no XOR logic needed
  on the frontend. This prevents BREACH attacks on HTTPS.
  ─────────────────────────────────────────────────

  For Thymeleaf forms: th:action automatically includes the XOR-encoded token - no extra work.

  For Postman testing:
  1. First, GET /product/add to receive a token
  2. Extract the XOR-encoded token from response headers or body
  3. Send it back in POST: X-CSRF-TOKEN: <the-long-xor-encoded-token>

  The client never needs to know about XOR - just send back what you received!
